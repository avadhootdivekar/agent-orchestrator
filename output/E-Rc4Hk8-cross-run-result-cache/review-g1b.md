## Further assessment

- **A hit never calls the budget gate, charge or reconcile.** The hit returns from `_prepare_and_maybe_dispatch` at `engine.py:1219-1224`, before the gate block (`:1229`) and before any worker, so `charge_estimate` and the settle-side `reconcile` are unreachable. The only budget call on the hit path is `reverse_estimate` for a stale previous-cycle charge (`:1534` via the helper). Test: `test_engine_result_cache.py:356-370` (I-6, spy sees no calls) and I-6b (stale charge reversed, `budget.resume_reverse` logged, mutation-checked by the developer).
- **Hit settle semantics.** The hit sets `status`, `outputs_present`, `started_at`/`ended_at` (engine clock) and the record's `ended_at` binding (`engine.py:1524-1532`), logs `task.end` with `cached: true`, adds to `done`, saves, returns `skipped` (`:1535-1541`), mirroring `should_skip`. The side effects that only `_settle_completed_task` has (post/pre hooks, verdict handling, `emit_tasks`/`output_manifest`, router, loop, breaker evaluation, head recording, quota timer reset) do not run for a hit. That is correct **because eligibility refuses every task that depends on them**: `pre_hook`, `post_hook`, `emit_tasks`, `task_manifest_path`, `output_manifest` (`eligibility.py:118-122`), router and loop members (`:242-246`), verdict-sidecar tasks without a declared sidecar output (`:265-267`), breaker verdict sources (`:268-271`). No consumer of `task.end` needs `exit_code` (checked by grep of `src/`). Shadow mode returns `hit=False` (`coordinator.py:383-386`), so the engine never settles from it.
- **Shadow mode never restores.** `coordinator.py:369-386` returns before `restore_outputs` (`:388`). Reviewer e2e: `AO_CACHE=shadow`, run, delete outputs, run again -> executor ran (dispatched), record `would_hit`, `hit False`, outputs produced by the agent only.
- **Concurrency at `max_parallel>1`.** `_prepare_and_maybe_dispatch` and `_settle_completed_task` run only on the main thread (`engine.py:899`, `:957`), so `state.result_cache`, `ctx.result_cache_pending`, the coordinator's `_disabled`/`_store_warned` flags and all store writes are single-threaded; no lock is needed and none is missing. The pending token is created at the lookup of dispatch cycle N, replaced or removed at the next prepare of that task (`:1500`), and consumed at a successful settle (`:1553`); a hit takes no worker slot. A sibling that commits or edits a tracked file between lookup and settle trips guard 2 or guard 3 and the task is simply not stored (safe, HLD I-19). Multi-process store safety is G1a scope. Reviewer experiment: 4 opted-in tasks at `--max-parallel 3`: all dispatched and all `stored: true`; outputs deleted, rerun: 0 dispatches, 4 hits, files restored.
- **Resume correctness.** Hit records are bound by `dispatch_cycle` and `ended_at` (`models.py:1335-1346`); `prepare_resume` keeps a succeeded task with present outputs (no new lookup, test I-8), and replaces a reset task with a fresh `TaskRunState` that carries `dispatch_cycle`, so the old record goes stale. Reviewer experiment: cache-on hit, delete outputs, `ao resume --no-cache` -> task re-dispatched, `status.json` has no `result_cache` key at any level.
- **Determinism.** No `datetime.now`, `time`, `random` anywhere in `cache/*.py` (grep clean); the coordinator and record builders use the engine clock passed in (`req.now`, `now`). Key and records contain no wall-clock value. The engine uses `self._clock()` for the hit timestamps; the existing `datetime.now(UTC)` calls elsewhere in `_settle_completed_task` are pre-existing.
- **SOLID/DRY/literals.** `ResultCacheHook` protocol plus injected `heads`/`worktree`/`cli_versions`/`environ` keep the coordinator testable (107 tests, fakes only); the engine depends on the protocol under `TYPE_CHECKING`. `_serve` isolates "after the key is known" and handles `CacheUnsafePathError` in one place. No magic literals found: reasons, events, bounds and modes are named constants; bench adds `_AO_NO_CACHE_FLAG`/`_AO_CACHE_OFF_VALUE` (`bench/subjects.py:91-95`). Duplication: S-3.
- **Error handling and logging.** One authoritative ERROR log with `exc_info` at the boundary (`coordinator.py:264-269,291-296,306-310`); no layer re-logs the same failure. `EXPECTED_ERRORS` is broad (`ValueError`/`TypeError`) by HLD design, so a programming bug in the cache logs one ERROR traceback per task instead of disabling; acceptable, and visible.
- **Reporting/NFR-1.** `runstate.py:246-250,290,321-322`, `usage.py` (`_current_hit_ids`, `_run_counters`), `outcomes.py:153-163`, `cli.py:274-277,334` import `cache.report` lazily and only for a non-empty `state.result_cache`; I-2 proves byte identity when off. Site A/B in `usage.py` skip current hits and keep real carried spend (hit-after-spend); `payload` omits `result_cache` when `None`.
